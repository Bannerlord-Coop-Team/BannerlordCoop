# Overpriced Raw Materials

Issue #3761, draft PR #3795. The implementation uses `Issues/Framework`; no legacy quest layer remains.

## Source and automated coverage

The inspected installation is Native v1.4.8. `TaleWorlds.CampaignSystem.dll` has SHA-256 `1F8E33E2ED73E6EC653D7629180AFB70649DDC6E5BD1657A802A264EFDA1C3AE` (assembly file version 1.0.0.0).
Full decompilations of `ArtisanOverpricedGoodsIssueBehavior`, `IssueBase`, `QuestBase`, `IssueManager`, `QuestManager`, and `IssuesCampaignBehavior` were inspected. Local diagnostic copies and test receipts are under the ignored `artifacts/quest-port-3761` directory.

`ArtisanOverpricedGoodsTests` runs real quest instances through `QuestScenario` and the production request handlers. The accepting client calls `QuestAcceptedConsequences`, including `StartQuest`; the server retains the constructor-created quest without starting it. The companion test prepares the troop deduction normally performed by the separate party-screen commit, then exercises real acceptance and completion. These are simulated E2E tests, not live-game evidence.

Duplicate and similar-commitment checks belong to `IssueAcceptPreconditions` and `SimilarCommitmentsPatch`, including lord solutions. Artisan-specific checks are vanilla market/merchant/relation eligibility, the lord owning the giver's town, companion Trade/Roguery 120, purchase funding, and delivery in the giver's town with enough remaining material. Trait XP follows the framework's existing suppression of the shared campaign trait store.

The old map-conversation fix is not needed by this accept path: the replacement framework has no conversation-tracker admission condition. The shared server issue-ID correction was cherry-picked from `1ebdf50a4`, retaining the three paths present on development and retaining upstream deletions for the conquest-specific paths.

## Pending live flows

No live test is authorized in this continuation. Run these after a supervisor assigns a lane, with a dedicated server and two clients. Start with Danustica (`town_ES1`, town `town_comp_ES1`); on the client in town, `coop.debug.settlements.list_notables` supplies actual artisan and merchant names and registered IDs. Use separate issues for mutually exclusive endings. Record the actual offer's material, quantity, payment and influence cost before each action.
