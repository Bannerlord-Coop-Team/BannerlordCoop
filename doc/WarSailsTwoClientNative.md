## Supported slice

Each client has its own synthetic main actor/captain, formation owner, player order owner and local helm. Formation orders, selection, oars-allocation switching, dynamic station management/repair, boarding/cut-loose, capture and weapons are **unavailable**. ## Bounded synthetic axes and focused motion observation

`native-axes-pulse` is a DEBUG `TwoClientNative` action, routed by the server to the selected ship's original owner, including when that owner is the elected simulator. It substitutes a finite lateral axis (`rudder` argument, [-1,1]) and a forward axis (`row=true` means 1; false means 0) into the same owner view `TickRowerInput`/`TickRudderInput` converters and complete input relay used by real keys. The argument is **not a direct rudder setting**: the native converter applies its deadzone, scaling and directional rowing/double-tap semantics. Zero/false is a bounded neutral-axes request. No keyboard injection, camera/focus write, agent promotion, placement, follower actuator or direct simulator command is involved.

All existing deployment/station, original-owner/slot, epoch-one authority, occupied own helm, actual native view, window focus/top screen and dialog/order/photo/ghost gates remain required. Normal helm range/focus must already have been established through the preceding protocol. Each mission/view tick checks current permission again. An unattended run that cannot satisfy normal focus or interaction must record `rejected:owner_helm_or_input_unavailable` and stop that scenario, not bypass the gate. Existing `helm`/`probe` commands are not substitutes.

A pulse has one server UTC deadline, at most one second, and an owner monotonic deadline derived from its remaining lifetime. All pulse publications reuse that exact UTC deadline, even though sequences increase at the existing 20 Hz cadence. There is no refresh or tick-loop extension. Duplicate operation IDs keep the original receipt and never restart; a different pulse is rejected while one is pending. Normal permitted expiry converts **zero axes with the current view's complete sail request**, then ends the synthetic publisher. `completed_axes_neutral_requested` means only that this normal completion record was dispatched, not that the ship stopped moving or cloth was neutralized. Ordinary keyboard input resumes independently; do not hold movement keys during this synthetic test.

Safety cancellation is different: permission/focus/mission loss, departure, fault/hold and missing-input host expiry retain the existing complete safety stop, **including raised sails**. Cancellation attempts a no-helm record through the existing authority-gated relay; when readiness is gone the existing authoritative hold and host deadman apply instead. If normal publication ceases after the completion record, its one-second host safety deadline still applies. The command never prolongs the 120-second fixture lifetime.
